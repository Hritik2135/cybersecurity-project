1. Introduction & Motivation

Security Information and Event Management (SIEM) systems are a cornerstone of modern Security Operations Centre (SOC) practice. Tools like Wazuh, Splunk, and IBM QRadar aggregate logs from hundreds of sources, correlate events against threat intelligence, and surface actionable alerts to security analysts.

Understanding how a SIEM works internally — from raw log ingestion through rule correlation to a live analyst dashboard — is critical for any cybersecurity engineer. However, enterprise SIEM platforms are complex, expensive, and require significant infrastructure to operate.

Mini-SIEM Lab was built to fill this gap: a fully self-contained, single-file Python application that demonstrates every layer of a real SIEM — log simulation, SQLite-backed aggregation, a regex-based correlation engine with stateful threshold rules, and a professional interactive dashboard — with zero external services and a three-package install.

The project is intentionally single-file (Hritik_Kumar_Prajapati_mini_siem.py, ~2,031 lines) so the entire implementation can be read, reviewed, and understood in one sitting — a design goal aligned with cybersecurity education and code auditability.

2. Objectives

  • Simulate realistic system log sources: SSH daemon, Apache web server, iptables firewall, sudo, useradd, and Linux Audit daemon (auditd).
  • Aggregate and persist all generated logs in a local SQLite database with proper indexing.
  • Implement a custom alert rules correlation engine with both stateless (regex match) and stateful (threshold-based) rules.
  • Map all detection rules to MITRE ATT&CK technique IDs for real-world threat context.
  • Build a professional, multi-page Streamlit dashboard displaying KPI metrics, live alert tables categorized by severity, event timeline charts, attacker intelligence, and analyst triage controls.
  • Implement a background daemon thread for continuous log simulation with an auto-refresh UI (Live Mode).
  • Ensure the entire application runs with only three pip packages and no native compiled dependencies.

5. Core Modules & Implementation

5.1 Log Simulation Engine

Six independent generator functions produce realistic log lines for each source:

FunctionLog SourceWhat it generatesAttack Scenario
_gen_ssh()sshdSSH login/failure (OpenSSH format)Brute-force, root login attempt
_gen_apache()apacheHTTP access log (CLF format)SQL injection payloads in GET params
_gen_iptables()iptablesNetfilter kernel logPort scan, reverse shell, exfiltration, REJECT
_gen_sudo()sudosudo syslog lineRoot shell, shadow file modification
_gen_useradd()useradduseradd syslog entryPersistence via new account
_gen_fileaccess()auditdLinux Audit syscall recordRead /etc/shadow, write /tmp executable

Each agent is mapped to a subset of generators appropriate to its role (e.g., firewall-01 only produces iptables logs). The attack_ratio parameter (0–1) controls what fraction of generated logs contain attack patterns.

5.2 Stateful SSH Brute-Force Detection

A key engineering challenge in SIEM correlation is stateful rules — alerts that should only fire when a pattern is repeated above a threshold, not on every individual event. Rule R001 (SSH Brute Force) demonstrates this:

Design: An in-memory dictionary maps each source IP to a list of time.monotonic() timestamps for recent SSH failures. On each new failure, timestamps older than 60 seconds are pruned, the new timestamp is appended, and the alert fires only when the bucket length reaches ≥ 3. The dictionary is protected by a threading.Lock to handle concurrent writes from the background thread.

5.3 Ingestion Pipeline

ingest_logs() processes each log dict in a single SQLite transaction: (1) INSERT the raw log row, (2) UPDATE the agent's last_seen and log_count, (3) call _run_rules() which evaluates all 12 rules and INSERTs any matching alert rows. All three operations are atomic — a partial failure cannot leave orphaned alerts without their triggering logs.

8. Live Mode & Background Thread

Live Mode makes the dashboard behave like a real-time SOC display. When enabled via the sidebar, two mechanisms work in tandem:

  • Background daemon thread (_bg_worker) — Calls simulate_logs(n=15, attack_ratio=…) followed by ingest_logs() every 10 seconds. Marked daemon=True so it terminates automatically with the process. All exceptions are swallowed to prevent the daemon from crashing.
  • UI auto-refresh — The sidebar executes time.sleep(10); st.rerun() at the end of each render cycle when Live Mode is active. This causes Streamlit to re-execute the entire script, pulling fresh data from SQLite and re-rendering all charts.
Thread-safety: The background thread writes to SQLite using WAL (Write-Ahead Logging) journal mode, which allows concurrent reads from the UI thread without blocking. The SSH brute-force tracker is additionally protected by a threading.Lock to prevent race conditions on the failure-count buckets.

Table: agents

One row per monitored host. Stores hostname, OS, role, IP, status, last-seen timestamp, and a running log count. Seeded from AGENT_PROFILES on first run; log_count is incremented atomically within each ingestion transaction.

12. How to Run

Prerequisites

  • Python 3.9 or higher
  • Install the three required packages:
pip install streamlit plotly faker

Launch

streamlit run Hritik_Kumar_Prajapati_mini_siem.py

The app opens automatically at http://localhost:8501.

Quick Start

  • Click ▶ Simulate & Ingest Logs in the sidebar to populate the dashboard with data.
  • Navigate to 📊 Dashboard to view KPI metrics, charts, and the live alerts table.
  • Enable 🔄 Live Mode → ▶ Start for continuous auto-ingestion and real-time refresh.
  • Visit 🔔 Alerts to triage alerts (Acknowledge, Resolve, mark as False Positive).
  • Use 🔍 Log Search with regex patterns like Failed password or UNION SELECT.
  • Explore 🎯 MITRE ATT&CK for the sunburst coverage map.

13. Conclusion

Mini-SIEM Lab successfully demonstrates all core capabilities of an enterprise SIEM system in a single, self-contained Python file. The project covers the full data pipeline — from synthetic log generation through correlation and alerting to an interactive analyst dashboard — while remaining accessible to anyone with a Python environment and three packages.

Key engineering achievements include: a thread-safe stateful brute-force detection rule using a rolling time window; a background daemon thread for continuous ingestion with graceful start/stop; a zero-pandas Plotly chart layer compatible with restricted execution environments; and a fully indexed SQLite schema with WAL concurrency.

The application was designed with code auditability as a first-class concern — every function has a docstring, every non-trivial line has an inline comment, and the layered architecture maps explicitly to real-world SIEM counterparts. This makes it an effective educational tool for understanding SOC operations, log analysis, and threat detection engineering.

All 10 automated tests pass. The application runs with a single command: streamlit run Hritik_Kumar_Prajapati_mini_siem.py
